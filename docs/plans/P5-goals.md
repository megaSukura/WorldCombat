# P5 阶段目标

> 当前表现方案（2026-09-16）：Photon 及技能视觉特效已归档；LDLib2 界面继续保留。下文的 Photon 检查、截图与特效验收条目属于历史记录，当前边界见[方案调整](../development/particle-presentation.md)。

2026-09-14。本文根据[完整计划](../../cobblemon_world_combat_plan_v0.3.md)、[P4 反馈](P5-entry.md)和[P5.0 讨论](P5-discussion.md)整理阶段目标。实施与选题同时遵循已认可的[内容结构及扩展约定](P5-structure.md)，具体技能、系统方案和实施批次继续审阅。

**P5 要做出一批有充分广度、可实际游玩的正式内容：让精灵的技能、个体差异、自主行为和玩家指挥共同参与 Minecraft 的战斗、探索、准备与世界活动。** 通过这批内容检验玩法、交互、表现和扩展能力，为后续完整游玩与全量制作建立可靠基础。

## 本阶段交付目标

| 目标 | 玩家与内容作者应实际得到什么 |
| --- | --- |
| 有广度的正式技能与组合 | 逐项手工设计有辨识度的技能、伙伴配招与组合，覆盖不同用途、行动方式、条件、代价、反制和世界作用。以既有 40–60 招作为选题起点，按代表性调整规模；原招式名称、介绍和设定提供灵感 |
| 在正常世界中形成玩法 | 观察、配招、采集、合成、建设与准备能影响实际遭遇；玩家可以自由使用工具、物品和武器，也可以侧重指挥与培养。代表性内容在正常野生行为、捕捉和再次探索中使用，并实际展示战斗以外的用途 |
| 培养与原生机制产生实际作用 | 让原生属性、培养、性格、特性、携带物和本批选用的特殊机制影响新的行动与世界用途。沿用捕捉、恢复、成长、进化、存储和交换的数据入口，并衔接背负／骑乘等原生交互；具体数值映射和姿态下的动作按内容设计 |
| 可复用且有差异的 AI | 野生精灵与伙伴使用同一技能能力，使用逻辑可在不同个体和用途间复用；物种、性格、当前目标与情境能改变实际行为。同一能力支持多种用法，技能变化后行为能相应调整；战斗、生活、探索、协作、恶作剧及工作可按内容扩展 |
| 每招自己的配置与准备状态 | 每个具体技能自行定义配置项、全局默认值和可调整的偏好，并支持个体对这招的设置。需要准备成果的技能可拥有跨施放状态；配置、状态与实际效果能通过 UI 理解，AI 和执行读取一致的有效值 |
| 连续、清楚的正式交互 | 完成圆盘指挥、快捷技能、精确选择、持续意图与自主行为设置的衔接；目标、地点、方向、范围和当前步骤有对应指示。所有逻辑动作可改键，包括鼠标确认与取消；原生 M 界面显示实际技能规则，同时保留有效的培养信息 |
| 有身份、有趣且可读的表现 | 技能的准备、朝向、移动、并行、打断和恢复关系由玩法决定，再配合表现。以 LDLib2、Photon2 和原生资源组合 UI、模型／材质、几何、轨迹、粒子、声音与瞬时反馈，表达技能特色、状态和结果；低画质仍保留必要信息 |
| 有实际用途的生态接入 | 优先通过 MC、NeoForge、Cobblemon 及常用 Mod 的现有接口实现功能。随正式玩法选定并完成对应的常用 Mod 联动；为 Create 等后续工作玩法同时保留世界操作、技能使用和 AI 的扩展方式 |
| 四层共同演进的创作基础 | 每个需求按职责拆分到核心 Mod、适配 Mod、可复用脚本库与最终内容；新增规则、行为、交互及表现可由脚本内容扩展。用正式内容发现和补齐共性能力，并保留核心在无 Cobblemon 环境下的独立性 |

上述目标共同约束选题：代表性来自玩法与组合覆盖，技能可以专注某种用途，也可以跨领域使用。P4 接入的基础在本阶段转化为正式体验，新增共性能力随内容需要补充。

## 每个技能拥有自己的配置

**配置内容由具体技能定义。** 每招各自拥有自己的字段、含义和可调整范围；这招的全局默认配置可以调整，个体也可以覆盖这招允许调整的部分。功能与 AI 偏好均按该技能自己的定义设置。对一招而言，全局来源就是这招自己的全局配置。

例如，某个火焰技能可以定义是否点燃方块及何时自主使用；某个储光技能可以定义自动准备的条件及保留偏好。两者分别定义各自的默认值与个体设置。这里仅说明配置归属，实际字段在技能设计时确定。

共享库提供读取、保存、校验、默认值与个体覆盖的处理，以及可复用的编辑构件；具体语义和必要的定制编辑由技能内容提供。**不建立所有技能共同遵循的统一玩法配置表。** 功能与 AI 的偏好也由各招按需要表达。MC、服务器和其他 Mod 既有的世界规则继续在实际操作入口生效。

配置描述偏好，运行状态描述当前事实。储光量等跨施放状态的消耗、衰减，以及收回、换招、卸载和重入后的处理由对应内容确定；短期状态是否写入存档按用途选择。UI、AI 与实际执行共同使用服务端权威结果。

## 技术选择与职责

**LDLib2 与 Photon2 已确定采用。** LDLib2 用作 UI 基础，Photon2 用作特效工具，结合已有脚本绑定和原生表现能力。具体发行版本、依赖组合及接入方式在实施时锁定并验证；当前结论表示工具选择已定。

界面与效果可以复用、组合、动态调整，也可以按需要创作资源和扩展构件。已有资源服务功能与时序设计。技能表现同时考虑美术身份、趣味和功能可读性，HUD、世界 UI、伤害属性／Miss／暴击以及情境反馈按实际信息需要组织。

复用顺序与四层职责沿用[架构约定](../architecture/effects.md)：Mod 承担通用执行与原生适配；具体效果规则、AI 策略、交互与表现编排在 TS／JS 中，由脚本库提供共用规则，最终内容决定具体玩法。优先使用 MC 已有效果，再沿 MobEffect 体系扩展，确有额外语义时补充独立状态；原生数据保持明确归属与唯一结算。各层均可修改，每次按实际职责判断复杂度的去处。

## 怎样判断 P5 完成

- 交付有充分广度的正式内容批次，玩家能感受到配招、培养、准备、操作方式和环境带来的不同结果，也能体验实际的非战斗用途。
- 同一技能在不同个体、不同使用情境或不同设置下能产生有依据的行为差异；新增技能、用途和组合有可复用的扩展路径。
- 圆盘、快捷操作、M 界面、世界指示与技能表现共同形成可理解的体验，玩家看得懂准备所得、作用对象、实际结果及失败原因。
- 技术检查按改动范围完成，操作、表现和玩法由用户或指定测试者集中试玩。首次联机使用前完成适用的基础同步检查；实现、技术检查与人工验收分别记录。
- 本批依赖的能力缺口已处理，其他发现明确归属后续内容或 P6；最终覆盖目标继续保留。P6 完整游玩、P7 发行维护、P8 全量制作的顺序沿用完整计划。

## 接下来的具体设计

阶段目标和结构方向已具备开始实施的设计条件。开发侧在开放结构中提出具体方案，用户反馈并审阅；能力信息、使用方法、AI 及交互继续由脚本扩展。具体内容需要说明的设计包括：

1. 正式技能、承载精灵、配招与特殊系统的选择，及它们共同覆盖的玩法。原 K01–K24、X01–X08 继续作为灵感素材，逐项重新设计。
2. 个体属性与性格如何影响行动，AI 如何组合使用方法，每招的配置、资源、时序与状态存续规则。
3. 圆盘、技能操作、个体设置和 M 界面的具体流程与表现，以及首批常用 Mod 联动和依赖版本。

据此形成可审阅的实施批次与试玩观察点，再按批准范围开发。整体规则与具体内容在设计和试玩中继续相互修正。
