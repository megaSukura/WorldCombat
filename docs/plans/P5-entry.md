## 全局议题与讨论方式

以下用于展开讨论，后续随新问题补充：

| 议题 | 需要具体讨论的内容 |
| --- | --- |
| 完整体验与阶段范围 | 收集、培养、配招、准备、战斗、捕捉和再次探索如何形成有意义的循环；P5 要让玩家实际玩到什么，与 P6–P8 如何衔接 |
| 玩家、伙伴与其他行动者 | 玩家行动与自主 AI 的分工、同时出战与伙伴选择、手动介入、野生行为、不同参与方式及合作；技能使用逻辑如何在生活、工作与战斗中复用，同时表达个体差异 |
| 技能、Build 与成长 | 技能创作的用途、时序、资源、代价和反制；属性、培养、性格、特性与道具如何共同形成打法；技能之间怎样组合 |
| 世界、原生机制与 Mod 生态 | 地形、挖建、工程和准备如何影响遭遇；捕捉、恢复、进化和生活行为如何融入世界；复用 MC、NeoForge 与原 Mod 接口，设计常用 Mod 的实际联动 |
| 操作、信息与表现 | 快捷操作、圆盘、精确选择、管理界面、施放者行为及效果表达；不同使用场景中的完整操作过程 |
| 内容选择与实现归属 | 代表性伙伴、技能、配招和遭遇如何共同覆盖玩法；每项需求如何复用现有系统并拆分到四层，哪些能力需要补充 |

整体与具体问题交错讨论：具体技能、AI 行为或界面步骤可以推动整体规则调整，整体规则变化也要回查相关设计。每轮区分已确认结论、候选方案和待讨论问题，重点记录决定、理由与未决项。讨论完整玩法时一并明确阶段归属；实施范围在讨论后审阅确定。

## 验收结论与测试内容退场

用户完成全部 P4 清单，未发现可识别的清单内功能故障，确认移动已使用原生速度。同时指出指挥面板、施法归属感和表现不满足正式体验。后续反馈由开发侧整理归属，用户直接描述实际感受即可。

旧测试技能、具体 AI 策略、指令菜单与线框表现退出默认内容；旧 G 模态面板及其宿主实现移除。必要的开发回归材料独立放入 `tests/content`，默认产物提供共享基础库。正式交互重新设计，原生数据、受控操作和仍有用途的通用机制按真实需求继续演进。

## P4 反馈带入的设计议题

| 主题 | 已表达的方向与需要细化的内容 |
| --- | --- |
| 圆盘指挥 | 围绕世界操作制作圆盘；目标、地点、方向、作用范围和当前步骤均有对应指示。复杂选择能连续完成，常用指挥减少视线与操作中断；原生背景模糊、文字及菜单的绘制层次一致 |
| 完整改键 | 所有逻辑动作进入 MC 快捷键设置，包括确认、撤回、取消、修饰键、技能槽和方向调整；键盘与鼠标走相同逻辑，提示读取当前绑定，结束交互后恢复正常挖建 |
| 技能属于施放者 | 按玩法需要选择准备、朝向与移动约束、执行和恢复，定义并行、等待、替换和打断关系。功能时序确定后，再利用或补充适合的表现资源 |
| 正式表现 | 同时追求技能身份、趣味与功能可读性；原生资源作为库和少量灵感。组合模型、材质、几何、轨迹、粒子、声音、HUD 和世界 UI，必要信息在低画质下保留；确定采用 Photon2 |
| 效果可识别 | “充电”样例的选择和链接可见，末端影响未被玩家识别。正式内容要能从受影响对象、状态、移动或其他世界变化看出用途；技术结算与可观察结果一起验收 |
| 培养、性格与 AI | 原生当前移动能力作为事实输入，进一步设计六维与培养如何影响即时战斗及世界行动；性格可以影响属性和战术偏好，具体映射放入领域脚本库和内容配置 |
| 原生交互与特殊机制 | 纳入 Shift＋右键的背负／骑乘及其进入、退出、施法和控制交接；原生道具、特性、个体特殊属性和其他机制按正式内容逐步成为即时战斗的一环 |
| 原生 M 界面 | 复用原界面的入口和个体／配招操作，让技能说明、资源、时序、范围、限制及相关效果显示本项目实际规则；需要保留的原生培养信息继续准确展示 |
| Buff／Debuff | 先使用已有 MC 效果，再考虑在 MC 系统内定义新效果；独立状态仅承担该系统难以表达的部分。原生异常、恢复和捕捉需要明确同步关系及唯一结算责任 |

每个技能各自定义配置、全局默认值及偏好，个体可以覆盖该技能允许调整的部分；共享层提供通用处理与编辑能力。跨施放准备状态及 UI 按具体技能设计，见[配置与状态目标](P5-goals.md)。

每招分别确定行动代价、可并行动作和可打断阶段，并让玩家能识别其选择。已有确认、撤回等通用改键已在本轮源码接入，实际操作随新交互复验。

## 复用与四层职责

先检查 MC、NeoForge、Cobblemon、KubeJS 及现有库已经解决了什么。确定采用 LDLib2 与 Photon2，接入时锁定版本并验证组合；常用 Mod 联动结合具体用途选题。技能设计与时序按玩法决定，再使用资源库；每个改动按需要拆分成多个部分：

| 层级 | 具体例子 |
| --- | --- |
| 世界战斗核心 Mod | 复用 MC MobEffect、碰撞和绘制，提供受控的施加／读取、动作阶段和通用表现操作 |
| Cobblemon 适配 Mod | 读取性格和个体数据，衔接朝向／姿态、骑乘／背负、原生状态与 M 界面 |
| 可复用脚本库 | 实现施法流程、状态组合、属性映射、圆盘交互构件、候选行动评价和表现组合 |
| 最终内容 | 选择某招的前摇和目标规则、某只伙伴的战术偏好、某个圆盘项目及实际说明和特效 |

例如“性格影响施法”可能同时包含适配层的数据读取、库层的映射与动作流程、内容层的具体参数，真实缺失的通用动作能力再补到核心。各层均可修改，按实际职责承担复杂度。

## 从讨论形成实施计划

以[P5 阶段目标](P5-goals.md)和[开放结构](P5-structure.md)推进实施与内容设计，按实际需要补充协议、共享能力和具体内容。既有的 40–60 招作为代表性内容选题起点，规模和组合由玩法覆盖需要调整；原招式名称、介绍与设定继续提供创作灵感。

方案经审阅后按批准范围实现。实施与试玩中发现的问题继续返回讨论，各层可按职责修改；P8 全量生产前处理影响内容生产的共性缺口。
