# P5 内容生产顺序

2026-09-17，根据最新讨论简化。作者唯一入口为[内容生产上下文](../CONTENT_AUTHORING.md)。

1. 准备可用的公共基础与资料入口。公共属性有完整默认；复用 MC 状态；原生配招之外的行动接入共用执行。独有机制跟随具体内容开发。
2. 在同一基线上，一次下发完整内容任务清单。独立任务使用各自源码工作目录，至少 10 路是用户期望的生产规模，实际并发按执行环境可用能力配置，持续补位。没有人工逐轮凑小批次的要求。
3. 作者交付独立单元及必要共享改动。集成时先合并共享依赖，再装配其消费者；修复只重跑受影响部分。独立作者只做语法检查；集成者的指定单元构建复用现有工具的 `--units`／`--selection` 和独立 `--output`。
4. 集成者统一构建和技术检查后交付可玩的正式内容。用户认可的范围记入[验收表](../authoring/accepted-content.md)，后续任务沿用这些范本。首次新内容可直接依据公共接口创作，无需先拿工程夹具当范本。

公共语义和独立内容可以继续扩展；遇到新共性直接形成共享改动。当前已提供作者上下文、原生资料查询与独立装配；外部 Agent 的派发和真实并发由执行环境负责。

P5 代表性正式内容、P6 完整玩法、P7 发行维护、P8 全量生产的阶段目标沿用总体计划。工具能够接收全部任务，不等于已经完成全量内容或性能验收。
