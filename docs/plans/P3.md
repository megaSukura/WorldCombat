# P3：原生能力适配与扩展边界

**状态：开发、后台技术检查及合并人工验收完成（2026-09-13）。** 按[完整计划修订路线](../../cobblemon_world_combat_plan_v0.3.md#sec-15)推进，与 P4 共同在 P5 前完成原生系统适配。实际结果及 P4 接续事项见[检查记录](../development/P3-checks.md)。

目标是让原生培养、属性、配招和其他可用功能在即时世界战斗中产生真实效果，并保持通用核心、领域适配与内容脚本的边界。P2 样机作为既有输入与生命周期的回归基线。

| 工作 | 可审查结果 |
| --- | --- |
| P3.1 原生能力梳理 | 按锁定版本列出数据、规则、操作与成长路径的适配状态；明确与 P4 的机制依赖以及 P5 前的完成条件 |
| P3.2 属性与培养基础 | 复用原生能力值计算，提供可用的领域快照；让培养、物理／特殊攻防和属性关系通过脚本影响实际结算 |
| P3.3 真实配招与资源 | 技能绑定读取原生配招，学习／遗忘／回忆后更新；招式资源、恢复和动作提交由唯一结算路径协调 |
| P3.4 成长与领域效果 | 衔接努力值收益、亲密度、学招与特殊进化记录；通过 P4 的效果协议实现状态、特性、携带及培养道具的适用效果 |
| P3.5 原生操作与生活行为 | 检查捕捉、恢复、队伍／PC、交换、形态及已有可用的世界交互；协调战斗控制与原生行为，补齐对应存储和所属变化处理 |
| P3.6 扩展与整合检查 | 核心继续独立运行；用领域能力驱动脚本样例，记录通用接口缺口并交由 P4 完善，接续增量机制与跨机制组合检查 |

本阶段已落地属性／培养基础、真实配招与 PP、成长收益与进化记录、原生道具及存储／所属变化、特殊球即时条件和原生行为交接，并通过[合并试玩](../development/P3-use.md)。P4 接续状态、特性、携带物、反伤／会心等效果协议及特殊系统依赖，结合移动速度和多伙伴观察完善 AI 边界，验证旧样例可移除、新内容可替换，再进入 P5。

原生持久数据由 Cobblemon 管理，快照供脚本只读使用；基础六维采用当前原生属性提供者计算，包括其性格与培养修正。配招映射、资源用量、新战斗时序、数值组合与机制规则由内容脚本表达；核心提供通用实例、提交事务、命中、结算和清理，适配提供受生命周期约束的原生数据访问。能力扩展应覆盖已知需求，也支持后来通过协议加入的机制。

技术检查按增量执行，使用独立隐藏专服与 `--nogui`；有变更才回测相应 P1／P2 路径。可见试玩按 [AGENTS.md](../../AGENTS.md) 另行确认，操作与玩法按批次交接。

P3 的相关功能完成后与 P4 合并核对：原生培养及属性实际生效，配招与资源一致，已确认原生功能可用，成长与存储有实际检查；已知机制需求及扩展验证满足第 8 节和 T03。随后进入 P5 的代表性正式内容设计。
