# P5.0 正式讨论记录

P5.0 为 P5 的正式环节。[完整计划](../../cobblemon_world_combat_plan_v0.3.md)提供项目基线，[讨论入口](P5-entry.md)整理全局议题及 P4 反馈。本文件按轮记录明确要求、探索性想法、事实调查、开发侧建议与用户反馈，变更已确认结论时说明替代关系。当前已形成[P5 阶段目标](P5-goals.md)与[内容结构及扩展约定](P5-structure.md)，具备进入结构落地与依赖接入的设计条件。

## 第 1 轮｜2026-09-14｜原生复用、生态与内容讨论素材

状态（第 2 轮更新）：下列 K01–K24、X01–X08 是讨论出发点与灵感素材。用户已明确其用途，尚未进入正式技能设计，也未确认这些设定。用户只阅读了部分技能，特殊系统尚未阅读；未反馈的条目继续作为素材保留。

### 本轮用户要求

1. 尽可能复用 MC、NeoForge、Cobblemon 及相关 Mod 已有接口；每项需求先检查已有能力，并按四层职责拆分。
2. 常用 Mod 联动是产品设计的一部分，需要提供有实际用途的原生接入。具体名单由提案与反馈确定。
3. LDLib2 在本轮由用户推荐，第 3 轮已确定采用；界面需求逐项选择实现方式。
4. 先说明原生系统、动画与特效的结构和现有资源量，让内容讨论有事实依据。
5. 世界持续运行，野生精灵、伙伴及玩家共同参与即时玩法。野生精灵可以表现为中立、友好、主动攻击、恶作剧或更复杂的特色 AI，具体行为由内容设计。
6. 由开发侧先选技能和特殊系统，给出具体意见，再由用户反馈。整体规则从这些具体讨论中一并推敲。

### 已查明的复用基础

依据锁定的 MC 1.21.1、NeoForge 21.1.250 与 Cobblemon 1.8.0。以下为源码、发行包及官方文档调查；动画和新依赖尚未在本轮逐项实播或集成测试。

| 来源 | 已有能力与本项目的使用方向 |
| --- | --- |
| MC／NeoForge | 复用实体移动与碰撞、伤害与效果入口、属性、物品和配方、标签、数据组件、GUI 层与输入事件。通用物品、流体和能量联动优先使用 Capability；让其他 Mod 能沿现有入口观察和处理我们的操作 [N1] |
| Cobblemon | 已接入的个体、培养、配招、捕捉、恢复和存储继续使用原生入口；另有姿态、动画播放、模型定位点、粒子发射器、表现时间线、骑乘和肩乘事件可供适配 |
| LDLib2 | 官方提供 1.21.1／NeoForge 路线，以及布局、样式、组件、数据绑定、KubeJS UI、HUD 和原界面内嵌能力。第 3 轮已确定作为 UI 基础；世界指向、连续输入和三维表现逐项选用已有能力再补充 [L1–L3] |

具体效果规则、AI 和 UI 内容继续由脚本库与最终内容承担。使用库时优先调用其现有脚本绑定；两个 Mod 提供实际缺少的宿主能力和适配。可复用的时间线执行能力也应先评估，技能编排与玩法规则仍属于脚本内容。

**原生表现资源盘点。** 直接读取本地 [Cobblemon 发行包](../../build/p0-research/cobblemon_jar.jar)；计数包含形态、变体及辅助资源，表示包内条目数量。

| 资源 | 数量 | 说明 |
| --- | ---: | --- |
| 精灵模型几何文件 | 1,142 | 包含形态等变体，使用时需结合模型选择与定位点 |

资源覆盖存在明显差异：皮卡丘有物理、特殊、变化招式动作和伏特攻击动作；杰尼龟有三类招式动作、奔跑及游泳；妙蛙种子的已命名动画主要是待机、行走、叫声、受击等。伊布还通过姿态定义组合程序化四足行走。以上作为可利用的资源库及少量灵感参考；玩法先确定效果与时序，随后选择、调整或补充适合的表现资源。

喷水、火焰与电击已有带贴图、帧动画、曲线和发射器的效果组件。正式表现可以组合这些资源、实体动作和实体／几何表现。原生时间线中的命中条件、等待和视觉位移需要与世界内真实判定及动作时序衔接：例如喷射火焰引用旧战斗命中结果，电光一闪包含模型平移和隐藏帧。资源选用应跟着新设计，命中、移动和中断由实际行动决定。

### 24 招讨论素材

名称沿用锁定版中文资料，下面的描述用于引出用途、规则和表现问题。内容、承载者、时序及操作方式均可重想；先讨论影响多个内容的共同原则，再开展正式手工设计。第 2 轮已移除 K01 的具体身体动作描述，功能时序与视觉动作分开考虑。

#### 动作与施法

| 编号／技能 | 我的建议 | 选择与反制 |
| --- | --- | --- |
| K01 电光一闪 | 短距离真实冲刺，可用于追击、脱离或抢占位置；准备、转向与恢复规则由玩法需求讨论 | 起步方向、路径和结束位置需要可读，碰撞与后续行动关系留待共同规则确定 |
| K02 喷射火焰 | 持续喷射，允许慢速移动和有限转向；主动结束引导后恢复原意图 | 持续占用施法机会，移动到侧后方、掩体后或打断准备可应对；点燃世界等用途与个体授权一并讨论 |
| K03 水枪 | 短促、有冲力的水柱，推动目标、灭火并冲散部分粉雾 | 推动受体型和抗性影响；可以救援或把目标推离有利位置，未必只追求伤害 |

#### 储能、天气与组合

| 编号／技能 | 我的建议 | 选择与反制 |
| --- | --- | --- |

| K24 大晴天 | 在局部建立稳定受光条件，改变光合作用、日光束及部分特性的使用机会 | 与求雨争夺环境优势；持续代价和空间影响由局部机制表达，MC 原有天气仍作为世界事实读取 |

首批可讨论的组合包括：妙蛙草围绕寄生种子、催眠粉、光合作用和日光束建立准备与持续控制；卡咪龟用水枪、冰冻光束和守住改变位置与通路；皮卡丘围绕充电、十万伏特和电光一闪安排准备、爆发与撤离。承载者和配招仍须结合原生学招来源核对。

野生 AI 直接使用相同技能能力。例如鬼斯利用光影与回声恶作剧，护食个体围绕补给行动，领地型个体示警后驱赶接近者，友好个体可提供协助。性格、环境和经历可影响选择，具体行为逐种讨论。

### 8 组机制与特殊系统讨论素材

| 编号／系统 | 我的意见与本轮需要反馈的设计 |
| --- | --- |
| X01 状态与行动资源 | Buff／Debuff 优先使用 MC 效果；恢复、清除和其他 Mod 的影响进入同一执行路径。睡眠等缺少合适标准效果的能力，优先扩展 MC 效果体系。技能资源建议保留原生 PP 的长期准备意义，前摇、引导和恢复承担即时行动代价，是否需要额外通用体力池留待具体技能比较 |
| X02 培养、性格、特性与携带物 | 以原生计算后的能力值为输入，已含性格修正的数值按映射使用一次。建议速度更多影响起步、转向和恢复，巡航速度结合物种移动方式；性格影响风险偏好与站位。首选讨论蓄电、叶绿素、恶作剧之心及树果、剩饭、讲究围巾，分别形成受击收益、环境倾向、扰乱时机、补给和配招取舍 |
| X03 天气、场地与元素关系 | 将求雨、大晴天、受湿、导电和冰面作为首批具体组合。读取 MC 的水、雨、火与光照事实，再以脚本库补充空间作用；每种关系都要在技能或世界用途上可见，并能与其他机制查询、组合 |
| X04 肩乘与骑乘 | 复用 Shift＋右键及原生姿态。建议肩上允许适合的远程／辅助技能，骑乘时保留驾驶与可用技能的配合。已查明肩乘会把个体转入肩上状态并移除独立实体，因此施放起点、受击、资源和控制需要专门适配；每种姿态的可用动作由内容决定 |
| X05 Mega 进化 | 倾向设计为一段职责变化：体型、移动方式、特性或技能动作出现明确变化，并有进入、维持与退出代价。可以先讨论一只偏控制、一只偏机动的候选，具体形态及取得路径再选择 |
| X06 太晶化 | 倾向围绕防御属性变化与同属性技能的一类额外行为建立 Build。先以少量清晰组合讨论，例如电系太晶强化可控传导；每个选择应有新机会与新的弱点，表现复用现有模型并补充可读材质／几何 |
| X07 Z 招式 | 倾向作为准备充分、施放可被识别的大动作：技能可产生关键救援、强控或区域变化。授权、使用机会、资源恢复及取消代价要适合持续运行的世界，由具体内容决定作用 |
| X08 极巨化／超极巨化 | 建议现在讨论其体型、碰撞、空间与团队作战意义，优先评估大型野外事件及开阔地使用。玩家日常使用的条件、破坏范围和复原方式另行细化，模型放大、碰撞与真实动作需要共同设计 |

X05–X08 的当前事实见 [P4 特殊系统调查](../architecture/P4-requirements.md)：锁定版包含部分形态、招式与个体字段，原生注册调查尚未找到相应启动道具。选用时需要明确原生可取得路径或附属依赖及适配，上述内容继续作为讨论素材。

## 第 2 轮｜2026-09-14｜多用途能力、行为差异、配置、状态与表现

状态（第 3 轮更新）：以下保留本轮方向、探索性问题与开发侧建议。配置归属按第 3 轮纠正，LDLib2 与 Photon2 已确定采用；AI 组合与具体状态规则继续设计，K／X 素材仍为讨论材料。

### 已明确的方向

- 原生动画、粒子和声音作为可利用的库与少量灵感，玩法决定功能、时序和行动关系。K01 的具体身体动作描述移出规则设计。
- 技能可以承担战斗之外的功能。AI 同时为生活、性格表达、探索、协作和工作保留扩展能力；Create 等联动需要同时考虑功能、技能和 AI 接入，实施时间按后续选择确定。
- 表现同时追求技能的美术识别度、惊喜和趣味，以及功能结果的可读性。HUD、世界 UI、瞬时文字和图标等都参与表达；现有头顶文字框属于需要改进的表现。
- Photon 在本轮由用户推荐，第 3 轮明确采用 Photon2；资源可复用、组合、调整和创作，内容表达的自由度继续保留。
- 当前技能与特殊系统是讨论素材。用户尚未读完技能，也未阅读特殊系统；先讨论共同原则，再正式设计内容。

### 本轮提出的问题

用户将以下内容作为讨论想法提出：技能可变时，AI 如何分层复用，同时呈现物种与性格差异；同一能力怎样服务多个领域；技能功能与 AI 如何提供全局及个体配置；储光等能力如何拥有跨施放状态并提供 UI 提示。

### 开发侧建议：复用能力的使用方法，组合个体的决定

技能执行定义“能产生什么结果”；使用方法说明“在什么条件下、怎样利用这些结果”；精灵结合目标、习性、性格、当前记忆和玩家设置选择方法、步骤与时机。同一技能允许提供多种使用方法；额外内容也能为已有能力补充新用途。

例如，喷水可以作为击退、灭火、灌溉或补水的素材。同一段射流执行可以复用，各用途分别判断目标、距离、完成条件和副作用。正在护卫的个体可以选择击退威胁；谨慎个体倾向隔着掩体工作或先拉开距离；好奇或爱恶作剧的个体可能产生接近、试探和引开注意的目标。具体性格映射仍待设计。

差异可改变目标选择、候选方法、接近路线、动作编排和停止条件；只调整评分权重不足以表达全部特色。通用行为组件承担大部分共性，独特物种或特性补充专门策略组件。新技能通常复用已有方法；新机制提供其对应的使用逻辑，AI 才能利用新的用途。

| 工程层次 | 在这一建议中的职责 |
| --- | --- |
| 核心 Mod | 复用原生观察、寻路、碰撞、执行和存储等能力，协调行动占用与生命周期，供不同任务共用 |
| 适配 Mod | 接入个体、性格、身体条件、原生行为及外部 Mod 的对象和接口；提供事实与受控操作 |
| 可复用脚本库 | 组合感知与记忆、目标选择、使用方法、任务步骤、策略修饰和执行反馈；复用战斗与工作共有能力 |
| 最终内容 | 定义技能实际效果及其用途、物种习性、性格修饰、工作或恶作剧行为，并组合库中的组件 |

这些是职责分解，仍可修改。技能、物种与性格通过组件组合产生行为，按真实差异补充专门内容。目标和用途是开放的脚本扩展；标签可辅助发现能力，实际的条件、计划和预测由对应逻辑提供。

工作联动可由机器或工作点提供需求、可交互位置和完成反馈，AI 再根据现有能力选择执行方式。换技能后重新检查可用方法，保留仍适用的目标和记忆；战斗、工作与生活行为共用行动协调。这里暂不指定统一规划算法或一套固定任务分类。

当前[共享 AI](../../content/tactics/world-ai.ts)已有候选与导航基础，候选上下文仍主要围绕交战。本轮建议的多领域目标、策略组合与个体配置尚待设计和实现。

### 配置讨论及第 3 轮纠正

本轮以火焰的点燃、供热和自主使用为例讨论配置。开发侧原先将全局规则、功能授权和 AI 偏好概括为一套公共结构；用户在第 3 轮明确纠正为：每个具体技能各自定义配置内容，拥有这招自己的全局默认值及可调整偏好，个体再设置这招允许覆盖的部分。当前约定见第 3 轮及[P5 配置目标](P5-goals.md)。

火焰是否点燃方块、何时自主供热等仅为字段示例；其含义、组合和编辑方式在对应技能设计时确定。

### 开发侧建议：允许技能拥有跨施放状态

以“提前储光”为例，需要表达的是个体持有的准备成果，而当前一次施放另有进度和执行阶段。状态可按职责分别存在：

| 状态 | 需要共同确定的语义 |
| --- | --- |
| 当前动作／输入 | 蓄力或引导进度、暂停或中断、结束后的处理 |
| 个体的准备成果 | 储光、储电、标记等的数量、消耗、衰减；收回、换招、离线和重入时如何处理 |
| 世界与工作状态 | 场地、目标、机器任务的归属、对象失效和卸载后的处理 |
| 个体配置与行为记忆 | 哪些是长期设置，哪些是短期观察、当前计划或可保留的经验 |

需要随个体保存的内容使用稳定身份和已有可扩展存储；持久化能力由宿主及适配提供，状态意义与退出／恢复规则由脚本定义。是否跨收回或离线保留，要按用途逐项讨论。

HUD、世界 UI、AI 判断与施放检查读取同一份权威状态。UI 可以表现存量、可用分支、剩余时间及失效原因；信息可见范围与表现形式按玩家需要选择。这样提前准备、个体设置和实际执行能够相互解释。

### 开发侧建议：表现设计的两个目标与工具

美术表达通过形状、材质、运动、节奏、声音、图像和文字建立技能身份与趣味；功能表达说明作用对象、范围、状态变化和结果。两者共同设计，既有动画的长度与骨骼动作按玩法时序适配，准备和恢复等规则由操作及策略需要决定。

Photon2 官方资料包含粒子、轨迹、光束、网格、材质、曲线、编辑器和可扩展渲染能力；官方 1.21 分支面向 MC 1.21.1 并声明 LDLib2 依赖。第 3 轮已确定组合采用 Photon2 与 LDLib2，并利用原生表现能力；具体发行版本、依赖组合和脚本控制方式仍需接入时核对，本轮没有安装或启动。

建议共享特效构件与 UI 构件，同时允许组合、动态参数、定制资源及新的扩展。技能脚本发出实际阶段和结果，表现脚本选择合适的世界效果、HUD、图标和瞬时反馈。伤害属性、未命中、暴击、工作完成、恶作剧或彩蛋可分别表达，频繁事件按需要合并并安排显示优先级。

例如“储光完成”可以同时有技能图标状态变化和短暂世界提示；“关闭点燃方块”应能在配置及相关预览中理解；恶作剧成功可以有专属的短暂反馈。现有头顶文字框需要与完整世界 UI 一起重新设计。

资料：[Photon2 官方介绍](https://low-drag-mc.github.io/LowDragMC-Doc/photon2/)、[官方 1.21 分支依赖](https://github.com/Low-Drag-MC/Photon/blob/1.21/gradle.properties)。
