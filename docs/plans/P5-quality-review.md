### 外部能力核实

锁定版本见[依赖清单](../../manifests/dependencies.toml)：Minecraft 1.21.1、Cobblemon 1.8.0、LDLib2 2.2.40、Photon 2.2.6.a。两个 Mod 均明确依赖 LDLib2 与 Photon2。

- **LDLib2 MC 主题可直接使用。** 官方文档提供 `StylesheetManager.MC`；锁定 JAR 内也有 `mc.lss`、MC 贴图和对应组件样式。主题转换需要同时整理内联样式，因为其优先级高于 LSS。[主题与优先级](https://low-drag-mc.github.io/LowDragMC-Doc/en/ldlib2/ui/preliminary/stylesheet.html)
- **Photon 能承担此次表现提升。** 锁定版本有 Shader Graph、自定义材质、模型、Trail、曲线、渐变及 Timeline 运行属性。官方提供可复用 Function Graph，适用于 UV 扰动、调色和溶解；曲线与渐变也可作为共享资源。[材质子图](https://low-drag-mc.github.io/LowDragMC-Doc/en/photon2/shaders-and-gpu/stages-functions-and-subgraphs.html)、[曲线与渐变](https://low-drag-mc.github.io/LowDragMC-Doc/en/photon2/particle-system/value-functions.html)
- **时间轴和游戏状态有明确的衔接方式。** 使用实例上的 RuntimeValue 注入状态，Timeline 驱动已绑定的可动画属性。同一属性需明确写入方，防止时间轴覆盖游戏侧设置；源资源可供多个实例复用。[时间轴](https://low-drag-mc.github.io/LowDragMC-Doc/en/photon2/timeline/animation-and-recording.html)、[运行时注入](https://low-drag-mc.github.io/LowDragMC-Doc/en/photon2/java-api/runtime-data-injection.html)
- **Unity 技法可以借鉴，落地使用 Photon 的渲染契约。** Shader 的粒子输入、实例化与透明深度需按 Photon 配置。锁定实现中部分自定义 GPU 数据节点在非实例化路径返回零，因此材质要检查实际渲染路径，必要时使用对应的材质参数输入。[Shader 输入](https://low-drag-mc.github.io/LowDragMC-Doc/en/photon2/shaders-and-gpu/extended-shader.html)、[模型与渲染](https://low-drag-mc.github.io/LowDragMC-Doc/en/photon2/particle-system/rendering-materials-and-meshes.html)
- **饰品有可复用的原生入口。** Curios 提供实体饰品库存查询与槽位接口，适合做训练师饰品提供器；其具体 1.21.1 版本和组合仍需在实施时锁定。原生携带槽继续属于 Cobblemon。[Curios 库存 API](https://docs.illusivesoulworks.com/curios/inventory/basic-inventory)
- **原生战斗脚本并不直接覆盖世界规则。** Cobblemon 官方明确其可数据包化的招式和特性效果运行于 Showdown 战斗引擎。复用身份、数据和有效接口，世界用途仍由本项目脚本定义。[Cobblemon 说明](https://wiki.cobblemon.com/index.php/Datapackable_Move_Effects)

## 三、建议实施方案

### 1．数值求值与正文说明共同设计

共享脚本层建立小而开放的“求值结果”约定：结果包含值、单位、可用状态和参与依据。技能可以直接提供常量或普通函数；常量自动形成最小结果，常见运算助手记录依据，特殊函数由作者补充自己的实际依据。值之间发生引用时记录依赖并检查循环，按实际消费者更新。伤害继续使用已有计算器，其他结果按自己的规则接入。

输入可来自施法者、目标、拥有者、环境、物品、其他状态、历史记录或内容自行定义的信息。结果可用于伤害、治疗、时间、范围、费用、行为条件等。每种结果自行规定有效范围；贡献可增可减，也可替换计算、改变条件或分支。共享层处理上下文、来源和生命周期，组合顺序及实际关系由所属机制决定。

一次实际结算输出它真正使用的依据，说明和 AI 预估调用同一规则。未选目标或当前缺少世界信息时，正文如实表达条件，悬停说明还需哪些信息；随机结果在命中后反馈。每招确定准备、提交、持续阶段分别读取什么，避免成长或装备变化让说明与正在执行的动作失去对应。

**玩家说明由各招写完整的可翻译句子，数字作为句中的富文本占位。** 例如日光束可写：

> 连续照射造成每次〔当前伤害〕点伤害，共〔照射次数〕次。消耗〔储光消耗〕份储光时，准备缩短至〔当前快速准备〕秒。

方括号表示可悬停的实际值，不是最终显示符号。悬停展开本值的参与属性、增减项、来源和条件；自定义规则同样提供自己的依据。范围、费用、时序、阶梯变化和特殊条件按语义写入正文，需要多少段由这招决定。

使用整句翻译键和可重新排序的参数，单位、来源名、状态、失败原因和偏好说明一并国际化。数字引用稳定标识，不再依赖中文标签或数组位置匹配。保留现有 Component 的排版与悬停能力，移除“全部数值”页。纯开发诊断另走开发入口。

界面以已有事件订阅更新相关值，保留展开、滚动和悬停状态。随时间变化的技能只更新它实际需要的进度；求值库不引入全局刷新面板的轮询。

### 2．逐招完善成长、偏好和辅助行为

现有 26 招全部进行设计复核。每招独立决定等级断点、变化项、变化幅度、代价与表现；采用原生精灵等级作为本轮成长输入。共享库仅协助选择阶段、求值和展示，阶段数及变化形式由技能决定。

先沿以下方向落实代表性内容，再以同一质量标准完成全部现有技能。这里的方向供本轮审阅，具体断点和数值在实施中的逐招设计与平衡核查中确定。

| 技能 | 本轮建议方向 |
| --- | --- |
| 撞击 | 保持简短冲撞，阶梯可改善收招或截击控制；不为展示系统增加额外资源。AI 提供最大追击距离、是否离开守卫范围等实用偏好 |
| 生长 | 分别设计积蓄效率与储光容量的成长阶段；自动积蓄可设置安全条件和期望储量，明确当前所得 |
| 日光束 | 围绕快速准备、有效照射或用光效率选取不同阶段变化；AI 可设置保留储光、现场聚光和等待射线清晰的偏好，持续光束始终可读 |
| 催眠粉 | 保留范围与浓度的真实取舍，在正文解释入睡所需接触；AI 提供避开已睡目标、覆盖追击路线等用法 |
| 甜甜香气 | 当前纯增益范围滑条建议退出玩家偏好，范围归于本招设计与成长；玩家选择搜索对象和何时自动使用 |
| 替身 | 保留投入生命与耐久的对应，成长分别考虑保护联系或存续能力；AI 可设置使用时机、生命保留及掩护位置选择 |
| 毒液冲击 | 保毒与兑现各有明确收益，独立设计阶段变化；AI 支持立即兑现、等待合适时机等偏好，并清楚展示实际分支 |
| 花瓣舞、落英缤纷 | 分别检查跟随旋转、定向集中和场地分隔的真实用途；等级变化服务各自节奏，范围与持续命中均能直接看懂 |
| 帮助、扎根及其他支援 | 检查受益对象、主动退出条件和操作辅助；成长可以改变支援方式或执行负担，简单效果保留简洁用法 |

每个玩家偏好必须回答“玩家为何选择另一个值或选项”。纯粹更强的数值可以保留为这招的全局设计配置，玩家侧改为有实际用途的偏好；有真实代价的设置在调整处同步说明收益与代价。目标能力由技能定义，AI 的目标偏好单独表达，避免把“自动选择自己”混成所有手动操作的限制。

每招继续拥有自己的全局默认值和个体覆盖。AI 设置可折叠展开，优先暴露难以逐次手操的时机、目标、资源保留、跟进和终止条件。共享 UI 处理编辑与保存，具体字段仍由各招提供。

### 3．性格、AI 与原生机制的组合

现有 AI 按“感知与记忆 → 产生候选 → 选择使用方法 → 持续任务 → 实际行动与反馈”演进。共享方法负责寻找、接近、等待、保持联系、撤退、持续作业等过程；技能声明自己能提供的用法。精灵和当前情境决定怎样组合，世界用途与战斗用途共用这些结构。

**性格作为独立内容提供行为贡献。** 每个性格可提供有名字的倾向、条件或行为组件；消费方按所需协议读取。谨慎可以影响暴露路线和退出条件，好奇可以影响探索候选，资源偏好可以影响等待和储备。这些是起始示例，新的行为维度和方法继续由内容注册。

本轮覆盖锁定版本已注册的原生性格，包括数值中性的性格。新增性格通过自己的定义或第三方提供器扩展；新增技能提供用途和方法即可参与已有决策。未提供行为定义的第三方性格使用明确的基础行为，便于作者补充。技能逻辑不再到处维护性格名单。

建议行为读取原始性格，属性计算继续服从原生有效性格，因此薄荷改变培养后的数值倾向，行为性格保持原意。此项已随本方案通过审阅。

消耗品、持有物、饰品和特性复用同一套“事实来源、规则贡献、作用生命周期和解释”基础，以组合库的不同实例与上下文承载各自规则，各自保留合适的原生接入方式：

| 来源 | 接入与共用方式 | 本轮交付 |
| --- | --- | --- |
| 玩家使用的消耗品 | 复用原生物品使用、消耗及事件；即时用途注册到相应使用方法 | 梳理当前已适配品，明确原生已执行部分与新增世界效果的归属 |
| 精灵携带物 | 读取 Cobblemon 携带槽，在换装、消耗和效果触发时应用或撤销规则 | 把当前分散的携带物效果迁入独立定义，连接数值依据、AI 与反馈 |
| 训练师饰品 | 建议以可选联动接入 Curios 原生槽位及变化事件，作为额外事实和规则提供器 | 锁定兼容版本，完成一项有实际用途的联动，验证装备、取下、失效和重入；具体物品随本批内容选定 |
| 精灵特性 | 继续以 NativeAbilities／WorldTraits 为基础，扩展到新求值和行为协议 | 复核当前规则的真实世界用途，补齐当前内容用到的触发、抑制、替换、恢复和说明 |

原生数据归原生对象，共享脚本组织效果，具体内容提供定义。新增规则的工作集中在自己的单元与确有需要的新机制上。身体移动、状态和物品接口继续优先复用 MC、NeoForge 与 Cobblemon。

### 4．可复用的结果反馈与表现构件

先把结果事件与表现渠道分开。实际伤害、抵挡、恢复、状态变化、资源兑现、失败及内容自定义结果携带必要的目标／最后位置、数值、来源、翻译键和表现提示。浮字、HUD、声音和 Photon 分别消费，某个渠道没有空位不会阻止其他渠道。

世界文字提供可注册样式与布局规则：有区别的字号、图标、运动与转场；同目标连续小伤害可合并并保留总量与次数，关键事件单独强调。距离、遮挡、重叠、可读时长和长句换行按实际画面调整。伤害、Miss、免疫、暴击、承伤、资源消费和自定义趣味事件都能沿同一入口扩展。低粒子设置继续保留必要信息。

Photon 共享资产与脚本构件分开负责材质表达和播放规则：

- **材质资源**：优先制作实际会复用的蒙版溶解、UV 流动、边缘强调与调色函数，使用 Shader Graph／共享 GLSL 和可编辑纹理。各招可组合，也可因独特需求制作专用材质。
- **形态与运动**：复用模型、Beam、Trail、范围边缘、命中与碎裂构件；曲线、渐变、缓动和噪声以资源共享。技能决定轮廓、节奏和组合，辨识度由整体设计产生。
- **时序与实例**：建立进入、持续、受击、正常结束、中断的编排约定；正常结束停止发射并播放尾段，中断立即撤销作用指示并允许装饰收尾，场景卸载走立即清理。使用 Photon 已有运行属性绑定衔接真实半径、方向、储量或强度，Timeline 与游戏更新各有明确的参数归属。每层配色及材质参数独立，保留作者设计的色彩关系。
- **创作产物**：保留 Photon 可编辑资源及其依赖，生成工具负责复用、装配和输出。源码附近说明专用流程的特殊理由，供后续作者选择参考。

这套构件首先服务下面的具体技能，并用于复查全部 26 招的准备、持续、命中和结束。画质分档主要减少装饰密度，真实作用范围、目标和关键结果保持清楚。

### 5．替身与毒液冲击的具体整改

**替身：建议保留草编替身身份，完成可辨识的代理表现。**

1. 建立时有明确编织成形过程，模型具备清楚轮廓；主人与替身短暂建立可读的保护联系，显示实际支付和耐久。
2. 保护中让玩家看得出替身正在工作。实际转移伤害触发替身受击、耐久变化及“替身承受”数字；主人得到相应保护提示。
3. 离开保护距离、遮挡或其他失效条件使用一次状态转变提示，恢复联系也有相应变化。
4. 击破时碎裂，正常到期时解编或溶解，持续效果随真实状态结束。无需逐物种克隆模型。

现有生命支付实际经过原生受伤链，替身耐久取实际支付；正文与反馈须准确说明这点，不能只显示请求值。验收必须能从正常视角看出“花了什么、谁在保护、挡了多少、何时失效”。

**毒液冲击：三种结果采用不同的动作形态。**

1. 未中毒：直接毒液命中，显示基础结果。
2. 保留中毒：毒性发生脉动，原有中毒标记保留，表达持续压制。
3. 消耗中毒：毒性向命中中心收拢后爆开，毒标记消退，出现“引爆中毒”等本地化结果文字和对应伤害。

命中结算保存最后位置及真实结果，移毒成功、保毒、免疫／抵挡与击败分别表达。目标死亡后也能显示应有的命中／击败结果；只有实际完成移毒才声称中毒被消耗。浮字和视觉各自读取结果，不再依赖事后仍存活的实体或另一渠道的成功。

### 6．G 圆盘、主题与原生提示

默认交互按本轮要求调整：**按住 G 打开并保持，左键进入中间节点，在可执行叶子上松 G 执行一次。** 叶子点击只选中；中间节点松开、中心空区松开均关闭且不执行。右键回上层，根层右键取消；Esc、失焦或伙伴失效时取消。输入离开菜单后恢复正常世界操作。需要继续选择目标的叶子，松 G 后进入该动作的选取步骤，并显示相应世界指示。

允许调整逻辑按键、菜单缩放、死区、常用项顺序与隐藏可选项；配置按稳定菜单 ID 保存，缺失项目可恢复默认。技能和精灵继续能添加、移除和组合节点。取消和返回始终可达，按键均进入原生改键设置。

统一采用 LDLib2 MC 主题，清理遮盖主题的重复内联色块、圆角和按钮样式。圆盘的扇区几何与世界指示保留自定义，用共享像素边框、字体、图标和交互状态统一视觉。偏好使用折叠分区，展开位置和编辑焦点在数据更新后保留。

原生“按 R 进入战斗”来自 PokemonRenderer 的挑战标签分支；“当前使用世界即时战斗……”来自我方 LegacyBattleGate 的取消理由，随后被原生 BattleBuilder 发到聊天。整改同时处理提示渲染、旧挑战发送分支、原生互动轮盘中的战斗／观战项，以及取消时的消息表达。原有战斗阻止规则继续生效，玩家侧不出现替代提示或空白消息。R 的放出／收回、原生 Shift 右键背负／骑乘及其他有效操作照常工作。

## 五、实施顺序与验收

本方案通过后建议按以下顺序推进，开发侧先完成可核查结果，再集中提供体验包，由用户按自己的时间启动。

| 步骤 | 交付 | 完成依据 |
| --- | --- | --- |
| A．贯通说明与计算 | 共用求值结果、整句国际化、句内数字悬停，先以撞击、日光束、替身贯通 | 同一上下文的执行与说明依据一致；能表达减益、环境条件和非伤害值；中英文换序与长文本正常 |
| B．贯通结果与表现 | 浮字独立事件路径、共享材质与生命周期；完成替身和毒液冲击 | 画面可辨识建立、实际作用、差异和结束；正常结束无硬切；致死和失效结果正确 |
| C．完善行为与原生来源 | 性格组合、实际 AI 偏好、持有物迁移及 Curios 联动 | 增加一个性格或技能无需修改全部对侧；装备与状态变化正确应用和撤销；行为差异在场景中可观察 |
| D．完成交互统一 | G 状态流程、MC 主题、旧提示清理 | 多级菜单松键执行准确，取消与改键可靠；世界操作和有效原生交互连续 |
| E．逐招完成并集中复核 | 26 招的独立成长、有效偏好、正文、AI 与表现全部复核 | 每招说明可理解，关键结果可读，成长与选择有理由；简单技能仍是简洁、完整的参考 |

A 与 B 的共用基础可以并行，C、D 按接口完成情况接入；E 覆盖全部现有内容，不止前面用于打通的几招。

技术检查围绕新增关系与真实边界：正负和条件贡献、非实体输入、逐招断点前后、不同对象共同结算；说明与规则一致；中英文与换行悬停；G 进入／返回／释放；性格新增与薄荷；物品换装、消耗、抑制及恢复；结果发生后目标离场；Photon 实际材质路径、资源重载和多实例生命周期。

**视觉检查必须包含实际画面。** 在白天、夜间、不同背景、远近视角、低粒子和多效果同时存在时，确认技能轮廓、范围和关键结果。CPU 产出顶点、发送了文字或后台转移了伤害，只作为技术证据。可见测试遵循既有批次约定，用户继续自行启动游戏。

本轮审阅范围包括上述结构调整、26 招质量复核、G 默认操作、MC 主题、原始性格用于行为的建议，以及 Curios 作为首个饰品入口的建议。实施与结果记录沿用上面的进度入口，具体实现以代码为准。
