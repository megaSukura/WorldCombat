# P2 执行计划：可试玩的伙伴指挥样机

**状态：P2 完成（2026-09-13）。** 两批试玩已有实际结果，头顶文字修复经用户复验通过，用户同意阶段收尾。检查范围与后续体验改进见[检查记录](../development/P2-checks.md)。

依据：[总计划的玩法与操作](../../cobblemon_world_combat_plan_v0.3.md#sec-05)、[P2 与工作包](../../cobblemon_world_combat_plan_v0.3.md#sec-15)、[P1 验收结果](../development/P1-checks.md)、[原型输入约定](../architecture/prototype-input.md)。

## 目标与首轮范围

做出一段能用正常键鼠完成的遭遇：玩家持工具开通道、调整掩体，伙伴守位或保护；玩家可快放攻击，也可预览岩障的位置与朝向后封路。切换为自主战术后，伙伴依据授权交战，玩家继续移动、用物品和施工。随后用原生精灵球捕捉野生个体，完成入队、放出、获得经验与保存重入。

首轮沿用一个主要受控伙伴、四个技能槽的原型规模，交付四个开发动作、一组可调整的战术授权，以及上述捕捉成长路径。具体按键、队列与成本以[参考配置](../../manifests/prototype-defaults.toml)为起点，在适配层落地并随试玩调整。

P1 已有动作执行、伤害与成长、收回清理和旧入口接管；P2 重点补上客户端输入与反馈、位置／方向参数、持续控制和世界作用。正式招式的批量语义、更多成长条件及长期联机体验按后续工作包推进。

## 玩家操作约定

| 操作 | 本轮预期行为 |
| --- | --- |
| 快捷技能 | 按技能键提交当前目标、落点或方向。默认使用独立技能键，同时提供可配置的“快捷修饰键＋数字键”预设；两者共用技能入口。 |
| 精确指令 | 按住精确修饰键，选择技能进入预览；视角选择落点，岩障预览中用滚轮调整朝向，松开修饰键确认。未选择或取消时结束预览。 |
| 持续意图 | 用短时指令面板选择跟随、守位、保护对象、关注目标，结合准星指定地点或对象；临时施法结束后继续当前有效安排。 |
| 战术授权 | 提供保守防护、自主交战两个起始预设，允许逐槽保留手动技能、调整追击范围和保护对象；捕捉准备时让本方自动攻击让出该目标。 |
| 状态反馈 | 技能栏显示可用性和冷却，伙伴标记显示当前意图与动作状态；距离、路径、资源或忙碌等问题给出可理解的原因。 |

主要受控伙伴与实际放出的个体明确对应，承接原有队伍选择、R 放出／收回及 M 摘要。切换时按动作阶段处理旧伙伴，再更新控制绑定和界面状态。

输入只消费当前交互声明的按键：滚轮调整朝向期间由预览接管，其余时候服务于物品栏。聊天、背包、其他界面、失焦、伙伴失效或内容重载会取消尚未提交的预览；已提交动作继续遵守自身的中断与冷却规则。

预览从伙伴的实际起点计算，标出主要阻挡、范围和朝向。界面分别表达预览、请求结果、接近、准备、执行与结束等适用状态；保护对象尚未被覆盖时显示接近过程。

## 四个代表动作

| 开发动作 | 要验证的玩法与能力 |
| --- | --- |
| 投射 | 复用 P1 示例，接入快捷键和目标预览；以真实路径处理命中与阻挡。 |
| 短时防护 | 为伙伴或指定友方提供短时减伤，维持期间占用行动机会，验证友方选择、持续效果和攻防取舍。 |
| 临时岩障 | 指定落点与朝向生成可阻挡移动和投射的临时地形，验证复杂预览、封路、拆除与到期回收。 |
| 短程冲刺 | 伙伴向指定落点或默认方向移动，沿途碰撞决定可达终点，验证位置输入、移动控制和地形限制。 |

动作过程、数值、授权条件和 AI 候选主要由脚本表达；核心按需要补充受校验的几何、移动、状态与临时地形能力。类型声明跟随可用接口维护，伙伴技能栏及领域规则继续归适配 Mod。

## 实施顺序

| 编号 | 工作 | 可审查的结果 |
| --- | --- | --- |
| P2.1 | 扩展行动参数与请求反馈 | 支持对象、位置与方向，让普通玩家指挥自己的有效伙伴；客户端提交意图，服务端核对控制权、有效个体、距离、参数版本、请求顺序与频率，并返回关联的状态和原因。保留 P1 示例作为回归路径。 |
| P2.2 | 接通输入、预览与技能栏 | 用投射动作先贯通快捷、精确、确认、取消、改键和阶段反馈，形成第一批输入试玩版本。 |
| P2.3 | 建立持续意图与授权 AI | 实现四种持续意图、两种起始战术及逐槽授权；脚本基于有限感知选择行动，宿主执行寻路与转向，并协调 Cobblemon 原有低层行为。 |
| P2.4 | 补齐代表动作与世界作用 | 完成防护、岩障和冲刺，让手动与 AI 使用相同动作与数值；预览和实际判定共享几何定义，完成临时资源清理。 |
| P2.5 | 串联原生捕捉与成长 | 复用精灵球及原生捕捉结算，验证成功入队、失败恢复、捕捉期间的攻击授权、所属变化后的旧句柄失效，以及经验与配置保存读取。 |
| P2.6 | 整理遭遇与第二批试玩 | 在有通道、掩体和高差的 MC 测试场景中加入少量会寻路和施法的脚本敌人，交付预置配置、场景准备入口与操作短清单；根据实际反馈修正输入、AI 和玩法问题。 |

先把 P2.1—P2.2 的输入链路交给用户体验，再逐步加入持续行为和代表机制。等待人工反馈期间，继续不依赖该反馈的开发；行为与世界作用整合后进入第二批试玩。

## 实现中的关键约定

- **手动与自主共用动作规则。** 手动请求在可执行边界优先，短期等待与替换遵循参考配置；动作阶段、冷却和目标有效性共同决定执行结果。技能结束后恢复有效的持续意图。
- **行为有明确边界。** 感知限于实际范围和可见信息，追击受授权区域约束；目标失效、路径不可达或超时会停止相关任务并反馈原因。战斗控制取得移动、朝向和目标的使用权，退出时释放。
- **设置与现场任务分开保存。** 战术预设、技能授权随个体保存；对象和地点意图在当前放出周期内有效。重新放出、离线或换维度后回到跟随，再接受新的现场安排。
- **临时地形尊重施工。** 岩障在通过权限与占用检查的空位生成，可拆除且无掉落；回收只处理仍归属该效果的方块。归属和到期信息支持卸载、重载及重启后的清理，玩家后续改建保留。
- **新内容继续走同一生命周期。** 防护、移动和岩障分别明确结束、中断、倒下与收回时的处理；捕捉成功只入队一次，失败后恢复有效状态。持续效果向相关客户端同步当前状态，迟到响应以当前指令为准。
- **按内容与协议版本检查可用性。** 客户端仅处理已安装内容的结构化参数与表现数据；版本或能力不匹配时给出具体原因。

## 验证与试玩安排

技术检查由 Codex 按实际改动完成，操作与玩法由用户或指定测试者试玩。

| 范围 | 检查重点 |
| --- | --- |
| 构建与模块边界 | 两个 Mod、脚本和类型可构建；核心独立执行代表动作，完整组合的专服正确加载；复查受本轮改动影响的 P1 路径。 |
| 输入与请求规则 | 未选技能松开、取消、重复／过期请求、越权与失效个体、迟到反馈、重载；资源与结果由服务端统一决定。 |
| AI 与生命周期 | 手动／自动竞争、技能保留、持续意图恢复、追击范围、失路、收回及换维度；动作结束后相关资源归位。 |
| 世界与存储 | 岩障拆除、玩家替换方块、到期、卸载和重启；捕捉／伤害／收回相邻发生时的唯一结果，以及伙伴成长和授权配置的实际保存读取。 |
| 第一批人工试玩 | 快捷与精确操作、按键重映射、取消、聊天／背包、失焦、切物品、重复按键；检查挖建共存、伙伴起点预览和低画质下的必要提示。 |
| 第二批人工试玩 | 对照手动协同和自主战术，体验守位、保护、封路、换位和原生捕捉；观察地形准备是否改变处理方式、失败反馈是否帮助继续操作。 |

本轮首先交付单人测试世界中的样机，通信与专服兼容随实现完成。首次安排联机时，按总计划 T05 在真实专服和至少两个客户端上验证施法、持续效果、中途加入与重连，再进入朋友试玩。

可见测试按[项目协作规则](../../AGENTS.md)逐批确认：启动前说明窗口数量、预计时长和人工操作。后台检查使用独立测试世界、隐藏启动进程和无 GUI 专服；反馈等待期间如实保留待验状态。

## 完成条件

1. 玩家能用正常键鼠完成快捷施法、精确岩障放置、持续指令和战术授权，并继续挖建与使用物品。
2. 四个代表动作具备一致的输入、服务端执行、反馈和清理；手动与 AI 均能遵循已授权的规则使用相应动作。
3. 一条原生捕捉、入队、放出、战斗成长与保存重入路径通过，临时地形和个体状态的关键检查完成。
4. 两批人工试玩有实际结果，发现的影响正常操作和数据的缺陷已处理；交付可运行版本、精简操作说明与实际检查记录。

P2 结果作为后续机制扩展与内容批次的依据。
