# 效果、机制与宿主分工

具体效果、机制库和 AI 由 TypeScript 编写，编译为 JS 在 KubeJS／Rhino 执行。两个 Mod 提供受控的世界操作、原生适配和生命周期。以原作名称、介绍、设定和效果为灵感创作新技能；培养、全量覆盖与扩展性继续遵守[完整计划](../../cobblemon_world_combat_plan_v0.3.md#sec-08)。

## 规则与执行的边界

项目按四层分配责任：世界战斗核心 Mod、Cobblemon 适配 Mod、可复用的脚本库、最终技能／AI／交互／表现内容。每一层都可以修改；一个需求可能需要拆成多个部分，分别放入合适的层。

| 层级 | 承担的复杂度 |
| --- | --- |
| 核心 Mod | 复用 MC 的实体、属性、状态效果、碰撞、网络与渲染机制，补充通用的受控操作与生命周期 |
| Cobblemon 适配 Mod | 接入原生个体、成长、配招、物品、骑乘／背负、界面与行为控制，维护数据归属和唯一写入 |
| 可复用脚本库 | 组合原生与宿主能力，提供动作流程、状态反应、属性映射、AI 与交互构件；通用库和领域库按依赖区分 |
| 最终内容 | 定义具体技能、角色战术、圆盘指令、界面说明和表现，选择并配置库中的能力 |

修改前先查 MC、NeoForge、Cobblemon、KubeJS 和项目已有实现，再拆分“已有能力复用、缺失的宿主操作、共享规则、具体内容”。按实际复用需求抽取库，复杂度的归属以职责和数据依赖判断。

P5 的[内容结构与扩展约定](../plans/P5-structure.md)明确：脚本可定义新数据、事件、查询、操作和协议，AI 的组成与决策、个体行为组合、输入和表现继续开放；具体协议随实际需要演进。每招自行定义配置项、自己的全局默认值及偏好，共享层提供通用处理能力。界面使用 LDLib2；技能视觉特效按[表现方案调整](../development/particle-presentation.md)暂时停用，后续采用 MC 粒子。

Buff／Debuff 优先使用 MC 现有效果；新增状态优先沿用其 MobEffect 系统。场地、跨对象关系和动作上下文等额外语义由效果协议补充。宝可梦原生异常的同步、恢复与捕捉要与适配层共同确定唯一状态和结算入口。这是下一批的实现要求，现有自定义状态尚未全部迁移；见[P5 入口要求](../plans/P5-entry.md)。

| 内容负责 | 宿主负责 |
| --- | --- |
| 定身何时触发、限制强度与持续时间 | 写入脚本请求的临时属性修正，到期释放所属修改 |
| 减伤、毒伤、恢复、吸收、反射及组合顺序 | 提供伤害事实、唯一生命写入、权限与事件分发 |
| 场地形状、材料、范围、触发、存续方式 | 方块／实体碰撞、放置权限、临时对象归属和恢复 |
| 感知筛选、记忆、目标、站位、导航重试、候选收益／成本／风险 | 有界观察、原生寻路请求、低层运动与控制交接 |
| 预览几何、动作和表现组合 | 验证、传输并绘制声明的数据 |

当前共享规则可直接查看[世界机制](../../content/mechanisms/world-effects.ts)、[原生规则](../../content/mechanisms/native-effects.ts)及[通用 AI](../../content/tactics/world-ai.ts)。已退场的技能和具体策略仅在[回归样例](../../tests/content/README.md)中保留必要材料，独立构建。编译后的 JS 是实际执行内容。

Java／Kotlin 新接口以通用操作定义。原生状态、PP、携带物和成长记录通过[领域入口](../../mods/cobblemon-world-combat/src/main/kotlin/dev/worldcombat/cobblemon/script/NativeMechanics.kt)写入；这些入口检查身份、当前值及所属，具体触发和数量由 JS 决定。

[临时变化](../../content/mechanisms/native-modifiers.ts)按独立效果覆盖当前原生事实，到期后重新读取当前值，保留期间的培养、特性与形态变化。[借用／随机调用和临时配招](../../content/mechanisms/native-loadout.ts)由脚本组织，共用原动作和原槽位的 PP 事务；技能栏、AI 与提交时检查使用相同限制。

携带物交换的玩法条件在脚本中。[原生双对象事务](../../mods/cobblemon-world-combat/src/main/kotlin/dev/worldcombat/cobblemon/script/NativeHeldItems.kt)先完成双方原生事件与身份核对，再一起写入，并发出原生同步及事后事件。这让取消发生在任一物品转移之前。

## 本次复查修正

完整计划复查后，将宿主中的导航超时／重试和跟随倍率移入脚本；水平冲刺改为脚本计算位移，再请求通用碰撞移动。原生捕捉事件由适配层发布通知，伙伴暂停／恢复目标的策略在脚本中处理。岩障的存续由脚本选择行动者效果生命周期，清理统一跟随所属实例。

旧客户端曾把所有落点技能预览成固定六格岩障。现在内容声明格子或半径，岩障实际放置与预览共用脚本形状。连续命中是否跨过 MC 受伤间隔也由脚本在伤害请求中声明。

保持 Mod 产物不变，仅加载[额外 JS](../../mods/world-combat-core/src/test/resources/worldcombat/script-extension.js)，在无 Cobblemon 的专服得到两组实际结果：

| 配置 | 原生移动属性 | 效果时长 | 脚本 AI 选择后的实际伤害 | 预览半径 |
| --- | --- | --- | --- | --- |
| root | 降到零 | 8 tick | 1 | 2 |
| slow | 降为一半 | 24 tick | 3 | 5 |

两组均按时清理并恢复原生属性。这证明了服务端效果、候选策略与声明式预览的脚本扩展路径；随后增加的 `workshop` 样例实际运行导电／声音组合。P4 人工验收后，上层测试内容退出默认包，旧模态面板实现移除。

## 稳定约定

自定义状态使用带版本的 JSON。脚本定义数据意义、校验、迁移、事件阶段及顺序依赖；运行时管理命名计时器、监听、来源、权限和清理。回调能力在返回后失效，持续写入由所属效果重新取得有效回调。

动作、行动者和持久效果具有明确生命周期。持久效果保存状态、剩余时间和命名处理器，恢复时核对原生身份及所属；首次创建回调只运行一次。迁移失败保留待修正记录，内容移除清理对应自定义状态。具体状态的退出／恢复语义由内容声明。

效果支持的刷新、解除、复制或传递通过命名操作声明；修改、先后顺序与复制规则在脚本中实现。事件回调失败会恢复该回调进入前的载荷；已执行的世界操作按自身事务和资源归属处理。

## 当前范围

场地、辅助对象、复杂输入及客户端脚本表现已有运行入口。输入的步骤与组合在脚本声明，服务端在开始及提交时核对范围、对象和版本；持续输入受动作实例和控制者约束。效果发布有版本的表现数据，随生命周期撤回，客户端从当前快照恢复范围和状态。绘图宿主的实现见[客户端入口](../../mods/world-combat-core/src/main/java/dev/worldcombat/core/client/ClientPresentation.java)，历史组合见[导电回归样例](../../tests/content/workshop/conduction.ts)。

临时地形支持当前可管理的方块生命周期，并保护已有方块实体。新容器、火焰、流体和下落方块需要额外的状态／传播管理，当前入口明确拒绝这些请求；完整能力按正式内容需要补充。其余原生效果、特殊系统及世界交互的后续归属见[P4 检查记录](../development/P4-checks.md)。
