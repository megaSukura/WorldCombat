# 复用脚本与新增内容

共享库负责运行约定和可组合的方法；最终内容提供用途、数值、策略、资源、文案与特殊流程。原生事实和调用由适配脚本连接。新增内容先声明依赖，再组合需要的库，独立注册新的协议和构件。

## 实现资料与创作范本

理解接口可查看[行为组合](../../content/behavior/composition.ts)、[工作任务](../../content/behavior/worksite.ts)、[技能目录服务](../../content/mechanisms/native-repertoire.ts)和[界面构件](../../content/client/library/)。创作范本采用用户已在游戏中认可的正式内容，范围遵循[内容创作约定](content-authoring.md)。

## 内容之间怎样协作

行为方法通过能力协议选择用途，宿主提供实时事实和操作。方法的匹配、对象、条件与额外动作可由调用方组合；范围和等待等策略参数也可按当前情境提供。物种、技能、性格和特性贡献不同的事实与策略，共同影响实际选择。

特性注册支持独立规则、追加贡献、显式替换和移除。事件名称及其数据由使用方定义；原生适配读取当前替换／抑制后的特性，再连接世界事件与行为。回调第三个参数是本次派发的特性身份，原生个体的当前特性则保留在适配上下文中。

每招拥有自己的默认值、配置文件和个体覆盖。共享目录承担原生配招、CAS、配置校验与默认动作时序；技能可扩展字段校验、详情、请求、菜单和完整执行过程。具体偏好含义仍由这招定义。

招式的执行参数与玩家数值说明使用同一来源；通用库提供登记、格式化和按需详情，参数及含义由各招定义。读取原生或外部事实时，说明应标明由谁提供，以及影响施法者、目标还是受益者。见[数值组合](../../content/mechanisms/action-parameters.ts)与[单源验证](../../tools/check-verdant-parameters.mjs)。


## 依赖与验证

内容按[独立单元](content-composition.md)装配，库与单元共用依赖图；组合选择见 [packs.json](../../content/packs.json)。构建逐库、逐单元检查其声明的依赖，防止完整发行包掩盖反向引用；核心包同时在没有 Cobblemon SDK 的条件下编译。`core`／`base` 提供独立库，具体内容按依赖使用。客户端库按实际调用加载原生 UI 类型。

常规构建包含独立消费者、原生 Rhino 互操作和包边界检查。新增共同能力应有独立消费者，已有内容则迁移到同一实现；技术检查和游戏操作体验各自记录。

技能特效及其共用库见[归档与后续方向](particle-presentation.md)。
