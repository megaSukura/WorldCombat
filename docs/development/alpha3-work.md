# Alpha 3：从抽查追查共因

本轮根据用户纠正，工作重心是已生成内容的共同问题：沿调用关系确认责任层，补共享能力或修错误调用，再处理受影响内容。机器工作同时从原生招式中拆出。没有重新组织批量生产。

## 根因与修复落点

| 共同问题 | 实际原因与处理 |
| --- | --- |
| 关系结束后仍留下定身/减速 | 来源失效时脚本回调不再可用，而原生 MobEffect 原本没有加入资源回收。Java 增加显式状态租约，正常结束、失效与保存边界统一处理；掷锚、捕兽夹、迷人、黑色目光、绑紧接入。普通独立状态保持自身寿命。 |
| 一层场地离开后误撤另一层保护 | 同一原生载体缺少多来源归属。共享脚本按来源/目标/令牌管理贡献，玩法继续自行聚合；反射壁、光墙、玩泥巴迁移。 |
| 反击不触发或不能实际伤害攻击者 | 在攻击者作用域把攻击者与自己判友；随后又把反伤当成攻击者自伤。反射壁、变圆、棱角化、灭亡之躯修正两个主体的关系判断；反射壁与棱角化的实际反伤由共享反应转交入口回到所属效果的合法来源。 |
| 续期/削短时长不对 | 原生剩余时长被当绝对时间再减世界 tick。回查修正念力、大闹一番、等离子浴、蓄力、胜利之舞；Java 数值本来正确。 |
| 通用动作强制至少一刻冷却 | 工作动作暴露了 Java 的零冷却拒绝，与可选节奏契约不符。现在支持 `commit(0)`，仍经过权限/费用事务，且不留冷却记录；负数仍拒绝。 |
| 工作依赖配招和 PP | 原有独立能力/工作入口已经足够，是上一版接错内容层。供能和曲柄各自成为可增删的工作单元，使用独立能力与菜单，不占配招、不扣 PP；原充电与辅助齿轮保留战斗用途。 |
| 多招附赠无用铺地 | 胃液、章鱼桶炮、烦恼种子、森林诅咒、生长、破壳、花疗、丛林治疗、茶会、日光束的主体机制不消费这些方块。移除十处装饰替换与专用参数/配置，保留主体机制、自然地面观察和粒子表达。实际屏障、挡路和锚点按其用途保留。 |

租约区分同刻刷新、第三方替换和新旧 owner，保存副本只过滤仍属于租约的载体。长期重绑每个 owner 只登记一份清理，不用固定上限掩盖记录增长。贡献管理与反应入口留在共享脚本；原生归属、保存与释放由 Java 负责。具体数值、时序、聚合方法继续由各内容定义。

## 技术结果与边界

- 受影响单元的静态检查及完整 profile 装配通过；统一构建和回归检查通过；独立 NeoForge 安装版 ready=true、正常退出且无脚本错误；共享贡献 9 项、合法来源反击 4 项回归通过。
- 原生状态租约后台检查通过：失效、同刻刷新、第三方替换、清除、来源/目标离场、实际保存/加载；4096 次刷新/重绑检查记录与清理数量不增长。
- 反射壁、光墙、玩泥巴、棱角化、掷锚、捕兽夹的同服场景通过；棱角化场景观察到实际近战受击与反伤。
- 空配招电属性伙伴的实际命令、走近 FE 接收块、重复指令保留作业、改令停供，以及 Create 曲柄正反转/停止均已通过隐藏专服整合检查。外观与操作手感仍由用户试玩，不以静态检查替代。

全量地形调用由 94 招/97 处降至 84 招/87 处。剩余部分未宣称逐项验收；临时可生长方块扩展后的恢复归属仍是待限定验证的问题，不能用本轮删去装饰树苗代替内核结论。
