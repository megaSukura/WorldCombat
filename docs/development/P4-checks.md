# P4 实施与检查记录

**2026-09-14：P4 功能验收完成，测试内容退场。** 用户完成全部清单，未发现可识别的清单内功能故障；同时提出指挥、施法动作、表现与原生复用要求，进入[P5 正式设计依据](../plans/P5-entry.md)。

## 人工反馈与处理

- 移动已经使用原生速度；用户认为整体偏慢，正式设计考虑六维、培养及性格对即时属性和 AI 的影响。
- G 面板操作不便利，模态流程打断世界操作，缺少指令目标／位置指示，背景模糊影响脚本文字。旧面板和宿主实现退场，下一轮制作带复杂选择和世界指示的圆盘。
- 当前技能缺少可感知的前摇、行动占用与朝向联系，粒子／线框表现过于简陋；正式技能按施放者的动作、阶段和实际影响一并设计。
- “充电”的场地选择、取消和另一个落点正常，实际影响未被用户识别，记录为用途和反馈需要明确；本次人工反馈不作为陷阱效果已确认的依据。
- 所有输入进入快捷键设置，包括选择／撤回使用的鼠标键；本轮源码已完成这些绑定，实际改键手感随新交互复验。
- 原生 Shift＋右键背负／骑乘、道具／特殊属性与机制、M 界面实际说明和 MC Buff／Debuff 复用均纳入下一轮设计要求。

用户无需先判断反馈属于故障、设计还是测试内容。开发侧记录实际观察、确定处理批次并说明实现责任。

## 清理后的交付

默认包仅含共享协议、世界机制和原生规则，测试技能、固定配招、具体 AI、旧指挥菜单及样例表现独立放入 `tests/content`，用于开发回归。旧 `CommandScreen`／`ScriptPanel`、旧场景命令及面板入口已移除。构建产物区分基础库和测试材料，`dist/` 同步清理历史样例。

旧构建缓存目录的删除被自动审批拒绝，返回 `blocked by policy`；本轮保留缓存。它们不属于当前内容清单，也不进入新产物。

以下“当前交付”与技术结果记录 P4 已实现和已验证的能力；旧 UI／样例的历史结果不代表正式设计验收通过。正式圆盘、M 界面、施法动作与 MC 状态复用尚待下一轮方案审阅和实施。

## 阶段交付记录

- 原生 HP、状态、特性、携带物和 PP 接入世界效果链；触发、数值、周期和组合在 JS。状态恢复、道具消耗、伤后记录继续使用原生入口。
- 通用机制包含持续光束、多段、打断、区域、限制移动、恢复、拉拽、辅助对象、声音观察、复制／传递、反射／重定向和受管理的临时地形。
- 多只伙伴分别保存意图、授权和动作；切换指挥对象保留其他伙伴的自主动作。感知、记忆、候选收益／成本／风险、追击和重试在脚本中实现。
- 临时能力等级、属性／特性与抑制、战斗特征复制、借用配招、观察／随机调用、封招及携带物交换形成可组合路径。具体变化、调用选择与 AI 候选在 JS；原生身份、成长和 PP 保持唯一来源。
- 多步骤路径、已有场地选择和持续控制使用版本化输入；手动与 AI 共用服务器校验及资源事务。
- JS 绘制技能栏、G 面板、状态文字及世界表现。G 可连续调整、切换伙伴；表现随实际效果创建和清理，并提供完整当前快照。
- `workshop` 使用全新的技能与 AI 配置，覆盖水路、潮湿导电、绝缘、场地链接和声音诱导；旧样例可通过内容配置整体卸下。
- 具体分工、原有越界及修正、保持 Mod 不变的 JS 扩展结果见[分层复查](../architecture/effects.md)。[内容组合](../../content/README.md)可单独装卸验证样例。

现有原生配招映射是机制验证材料；P5 按名称、介绍、设定和效果的灵感手工创作正式技能。原生培养、丰富度、全量覆盖和核心独立的要求继续有效。

## 复查方式

JDK 21 环境中，在项目根目录执行：

```powershell
.\gradlew.bat --gradle-user-home .gradle-user -I tools/export-server-checks.gradle build assembleDist exportServerCheckLaunch
python tools/check-server.py core --p4-workshop
python tools/check-server.py full --p4-workshop
python tools/check-server.py core --p4-world
python tools/check-server.py full --p4-native
python tools/check-server.py full --p4-combinations
python tools/check-server.py full --p4-combinations --restart
python tools/check-server.py core --p4-script root
python tools/check-server.py core --p4-script slow
python tools/check-server.py core --p4-effects
python tools/check-server.py core --p4-effects --restart
python tools/check-server.py full --p2-movement
```

专服显式 `--nogui`，后台执行。本轮重新检查了核心机制、原生配招／PP 和临时变化／调用路径；现有保存、迁移与包移除结果继续作为对应功能的依据。

## 交付与验收

`dist/` 默认使用 `base`，包含双 Mod、共享脚本库和 SDK；核心单独使用 `core` 组合。开发回归材料另行构建至 `build/test-content/`。该次人工试玩使用的冻结副本和清单保留历史记录；本轮清理在源码与新产物进行，运行中的游戏由用户安排保存和退出。

当前快照的协议和清理已有技术结果。用户完成整份清单，交互和表现的具体意见见本页；首次真实联机的两个客户端加入／重连仍待安排。
